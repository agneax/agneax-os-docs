# 08. How We Work

Learn about our versioning strategy, release cycles, and public issue tracking workflows.

---

## Versioning Strategy

Agneax OS follows a structured versioning format:

$$\text{Major} . \text{Minor} . \text{Patch}$$

- **Major (`v1.0.0`)**: Significant system milestones, major user interface redesigns, or architectural platform updates.
- **Minor (`v0.1.0`)**: New feature introductions, upgraded native applications, and system-wide usability enhancements.
- **Patch (`v0.1.1`)**: Targeted bug fixes, security updates, and performance optimizations.

---

## Release Channels

1. **Stable ISO Releases**: Thoroughly tested images published via [GitHub Releases](https://github.com/agneax/agneax-os-docs/releases). These are intended for production use on workstations and laptops.
2. **Rolling System Updates**: Incremental patches and library updates distributed securely through the native **System Updater**.

---

## Issue Management Workflow

We track all user-submitted bugs and feature requests via the [agneax-os-docs/issues](https://github.com/agneax/agneax-os-docs/issues) tracker.

When reporting an issue:
1. **Search Existing Tickets**: Verify that your bug or idea has not already been submitted by another user.
2. **Use Official Templates**: Choose either the **Bug Report** or **Feature Request** template.
3. **Provide Detailed Logs**: Include your hardware specifications, step-by-step reproduction instructions, and clear screenshots where applicable.
